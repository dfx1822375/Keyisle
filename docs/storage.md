# 本地加密存储

本文说明 1.0.0 的本地存储。主密码界面、账号管理和悬浮搜索共用同一个解锁会话，正常启动不载入示例数据。

0.11 沿用 schema 2。新增的 `theme.txt` 只保存四个固定配色名称之一，不保存账号或密码；与快捷键、锁定和启动设置一同保存，失败时回滚原设置。

## 技术方案

使用 rusqlite 操作 SQLCipher。数据库包含账号名称、用户名、密码、分类、标签、网址和备注，所有字段均保存在加密数据库中。主密码通过 `sqlite3_key` 传入，不进入 SQL 文本。程序启动存储会话时检查 `cipher_version`，避免把普通 SQLite 当作加密实现。

Windows 使用 SQLCipher 官方支持的 LibTomCrypt 后端，静态编译进程序。Linux 验证端使用 WSL 已有的 OpenSSL 开发库。两个后端均来自锁定的 SQLCipher 源码版本；通过双向互读检查文件兼容性。Windows 用户不需要安装 OpenSSL。

Windows 原生库由 `native-sqlcipher` 构建。脚本先生成原生库，再把生成目录传给 rusqlite。此顺序用于满足 Rust 对原生静态库的编译期检查，避免依赖 Windows 的 `nmake`。

参考 [SQLCipher 设计](https://www.zetetic.net/sqlcipher/design/)、[SQLCipher API](https://www.zetetic.net/sqlcipher/sqlcipher-api/)以及 [rusqlite 构建说明](https://github.com/rusqlite/rusqlite)。源码包和许可信息见 [sqlcipher-src](https://crates.io/crates/sqlcipher-src)。

## 保存与备份

创建密码库使用排他创建，已存在的文件会被拒绝。增删改均使用事务；失败时返回错误，不把失败操作视为保存成功。业务内容通过 SQL 参数绑定。

临时存储使用内存。Windows 构建还将 `SQLITE_TEMP_STORE` 固定为 3，并关闭动态扩展加载。密码字段的 Rust 所有权对象使用 `Zeroizing` 清理；这不代表已经消除了 UI、系统和数据库内部的所有明文副本。

使用 DELETE 日志模式和 FULL 同步。备份时先取得写事务保留锁，阻止其他连接写入，再复制已提交的数据库文件并同步目标文件。备份前执行完整性检查，备份保持原有加密，并禁止覆盖已有文件。修改已有账号前自动备份，默认保留最近 10 份。清理失败时可能保留更多文件。单个或批量删除账号均在一个事务中提交，且不生成新备份。恢复界面复制为独立工作副本，重新解锁成功后才更新最近密码库路径，原库保持不变。

密码派生及加密参数沿用 SQLCipher 默认值。密码库不会直接由 KeePass 打开；当前不提供 KDBX 导入导出。

“设置 → 默认备份目录”指定手动导出及恢复的起始目录。留空时使用数据目录下的 backups 文件夹，所选目录不可用时也暂时从这里打开。对话框内临时选择的路径不改变设置。备份管理会同时显示软件管理的备份与默认目录中已有的 .db 文件。恢复时用备份自身的密码验证，删除目录文件前则核验 Keyisle 格式及当前库主密码，防止误删其他数据库。

## 主密码与本地备份管理（0.6）

改密及清理覆盖当前用户数据目录内符合软件命名规则的自动备份和升级前备份。手动导出副本、独立旧库不纳入自动改密或清除，避免把任意 `.db` 当成备份处理。目录链接、非普通文件及越界路径会被拒绝。

改密使用 [SQLCipher 的 `sqlite3_rekey` 接口](https://www.zetetic.net/sqlcipher/sqlcipher-api/#sqlite3_rekey)，对加密副本逐个更换密钥并重新打开验证。准备期间保留全部原文件；只在全部副本通过完整性检查、落盘及新密码验证后写入提交标记。升级前备份保留原数据库结构版本。

切换通过同一文件系统内的重命名完成。`master-change` 内的记录只保存相对文件名和阶段，不保存主密码。提交前中断清理临时副本，提交后中断继续切换；切换完成标记与清理阶段分开，避免清理中断导致无法恢复。Windows 使用带写穿透标记的文件移动。启动时先取得单实例保护再恢复，恢复失败拒绝继续打开密码库。

改密期间会话锁定且禁止重复提交；系统锁定会取消尚未提交的准备工作，已提交的切换会继续完成，但不会重新解锁。任何本地备份密码不一致、损坏或无法写入时，不会跳过该备份并宣称全部成功。切换失败保留恢复记录，提示重启并在恢复完成后使用新主密码。

清除备份需当前主密码、范围数量确认，并逐个报告失败；当前库不进入清单，外部副本不变。清除后自动备份规则继续生效。普通删除不等于物理安全擦除，旧加密文件痕迹可能仍可从底层存储、系统快照或其他副本恢复。

## 敏感标记与旧库升级

账号表的 `sensitive` 字段保存在 SQLCipher 加密数据库中，跟随加密备份及恢复副本保留。格式版本从 1 升至 2；首次打开旧库时先检查并保存升级前加密备份，再在事务中添加字段。旧记录默认不是敏感项，旧版应用会拒绝不支持的新版格式。

查看或编辑、删除、三种填充共用验证入口，在批准前不读取该操作所需的密码字段。授权绑定记录、操作、会话代次和短期请求；只消费一次，取消、锁库、窗口变化或动作无法完成时不保留供后续使用。

主密码复验使用独立只读 SQLCipher 连接验证当前密码库，不缓存主密码。Windows 验证提供两个入口：

- Windows 账户密码：Windows 系统凭据弹窗在短时验证进程中收集信息。系统返回的序列化缓冲区直接交给 `LsaLogonUser` 验证，并比较令牌的用户 SID。仅当前运行账户可以授权；应用不将缓冲区解包为密码字符串。主进程只通过私有匿名管道接收成功结果，输入管道仅传递当前操作标题，不传递密码。验证进程正常返回时清零并释放凭据缓冲区；取消、锁定和 60 秒超时会终止该进程。Job Object 的 KILL_ON_JOB_CLOSE 约束用于防止主程序退出后遗留验证进程。进程强制退出由 Windows 回收内存，不承诺系统中所有副本已擦除。不会试探空密码，不自动重试系统登录。
- Windows PIN / Hello：由窗口线程发起桌面互操作请求，后台等待结果。只在 Windows 返回 Verified 时授权，不读取 PIN、指纹或人脸数据。接口不可用时可以使用账户密码或密码库主密码。

Windows 账户密码、Windows Hello PIN 和密码库主密码是不同凭据。账户密码或 Hello 仅用于已解锁库的敏感操作复验，不能代替首次解锁时的密码库主密码。

参考 [Windows 凭据窗口](https://learn.microsoft.com/en-us/windows/win32/api/wincred/nf-wincred-creduipromptforwindowscredentialsw)、[LsaLogonUser](https://learn.microsoft.com/en-us/windows/win32/api/ntsecapi/nf-ntsecapi-lsalogonuser) 和 [IUserConsentVerifierInterop](https://learn.microsoft.com/en-us/windows/win32/api/userconsentverifierinterop/nn-userconsentverifierinterop-iuserconsentverifierinterop)。

这是操作保护，并非独立加密层。当前不包含独立密钥的敏感密码库，也不防御已控制系统或能够读取进程内存的攻击者。

锁定设置保存在当前用户的 `lock-settings.txt`，没有账号、密码或敏感标记。默认电脑空闲 5 分钟，可选 1、5、15、30、60 分钟，或改用密码库无操作计时。原生线程与界面共用同一个计时策略，文件对话框不会暂停自动锁定。`shortcut.txt` 只存全局呼出快捷键；新组合先注册、再保存，成功后才释放旧组合。设置文件不含凭据。

## 验证方法

在 WSL 项目目录执行：

```bash
bash scripts/verify-storage.sh
```

脚本使用独立临时目录和固定假数据，验证后清理。测试不访问 Chrome、aTrust 或真实账号。

检查内容包括：

- 创建密码库、增删改查、关闭后重新解锁。
- 错误主密码及损坏文件被拒绝。
- 名称、用户名、密码和分类没有以原始明文形式出现在主数据库文件中。
- 已有密码库和备份不能被覆盖。
- 模拟写入失败时，原记录保持不变。
- 加密备份可以重新打开，保留备份时的原记录。
- Linux/OpenSSL 写入的数据库可由 Windows/LibTomCrypt 打开，反向也成立。
- 实际启用的 SQLCipher 版本、加密后端、内存临时存储与 KDF 参数符合预期。

错误密码和损坏文件测试会产生 SQLCipher 的 HMAC 错误日志。这些日志是预期拒绝行为，最终以脚本退出码和测试结果判断。

## 当前边界

已完成主密码、账号管理、锁定、备份恢复和 Windows 填充回归。原生线程在锁定和退出时取消本进程的标准模态窗口，避免文件对话框阻塞锁库。系统锁屏和休眠的自动测试通过向本应用发送通知模拟，没有实际锁定或休眠用户电脑。已实测配置为 1 分钟的密码库无操作锁定，其他窗口持续输入不会续期；默认电脑整体空闲 5 分钟、多显示器、真实 aTrust 及输入法仍需人工验收。Windows Hello 当前检测为不可用，其主密码回退已测，真实 PIN、指纹或人脸的成功路径尚未实测。尚未覆盖断电、进程被强制终止、磁盘硬件故障和长期使用，事务失败模拟不能代替这些故障测试。

## 单份备份与启动设置（0.7）

备份列表复用本地清单范围和链接检查，按文件名的原始纳秒时间排序。单份和批量删除均先验证当前库主密码，再核对确认时选中的文件是否仍在清单内。文件逐份删除。遇到占用或权限错误时，界面报告已成功删除的份数。正式库排除在操作范围之外。默认目录之外的导出文件可通过恢复对话框手动打开。恢复验证备份主密码，复制为有限大小的独立文件并检查完整性，只有会话代次及取消标志仍有效时才能接受结果。系统锁定或过期结果不重新解锁。

启动偏好文件不含密码；启动登记使用当前用户 `Software\Microsoft\Windows\CurrentVersion\Run` 的 `WindowsPasswordManager` 值，路径带引号并检查长度。只在用户保存启动设置时写入；配置文件提交失败时尝试恢复原启动项，恢复失败明确提示，不把失败报告为成功。原生测试使用 `Software\PasswordHelperTests` 临时键，不写实际 Run 项。

## 搜索、最近使用与统一设置（0.8）

`usage` 表与账号表位于同一 SQLCipher 数据库，通过账号 ID 关联并随删除级联清理。只保存最近一次完整填充成功的时间，以微秒时间和递增下限保证顺序；取消、失败和中断不写入。更新使用时间不为每次填充创建自动备份，后续正常加密备份包含该表。旧库解锁时按需创建此表，数据库格式版本仍为 2，0.4～0.7 可继续读取账号内容。

搜索只使用摘要中的名称、用户名、分类、标签和网址，不加载密码或备注。拼音转换完全本地执行，不发送网络请求。名称和标签权重较高，查询结果先按匹配分数，再按最近成功使用时间排序。

统一保存先校验全部输入并保留原设置文件，注册新快捷键但暂不释放旧快捷键；全部写入成功后才替换运行中的快捷键与锁定规则。中途失败会撤销新注册并恢复文件；恢复失败明确提示。启动项写入复用原有注册表回滚。此流程处理常见写入失败，不保证注册表与多个文件之间断电原子提交。设置文件不包含使用时间或任何密码。

按键录制仅在设置页明确开始录制时创建临时低级键盘钩子，同一 exe 的短时隐藏辅助进程处理消息，并仅在密码助手窗口位于前台时捕获有效组合。捕获、取消、失焦、离开或退出即释放；辅助进程受 Job Object 保护，主进程退出即终止；3 秒未就绪或 90 秒未完成会取消。不记录普通输入，不持久化键盘事件。录制允许识别外部程序已注册的组合，保存仍重新注册检查冲突并保留原设置。

## 一键还原与窗口偏好（0.12）

appearance.txt 记录 system/light/dark；window.txt 保存正常窗口的工作区坐标、逻辑尺寸与最大化状态，不含账号或秘密。保存设置的快照包括快捷键、锁定、启动、配色和外观五类文件，窗口布局独立保存。

还原只处理明确管理的 vault.db、restored-*.db、升级前备份、backups/auto-*.db、对应 SQLite 辅助文件及已知设置/临时/回滚文件。清单最多 4096 项，拒绝链接、重解析点、目录穿越、重复及未知名称。当前库主密码验证后，将有版本的清单同步写入 reset-pending，持久提交前可取消。提交后逐项删除，标记最后删除，失败保留标记以供继续和重启恢复；不递归删除未知文件。开机启动登记经当前用户接口单独移除。

删除成功后以全新进程建库，旧主密码不再作为当前凭据；手动导出的外部加密备份仍能用原密码恢复。普通文件删除无法保证存储介质残留不可恢复。

## 应用内最近使用与只读详情（1.0）

新增加密表 application_usage，以应用文件名和账号 ID 为组合键，保存最后完整填充成功的时间；全局 usage 与应用时间在同一事务内提交，删除账号时级联清理。沿用 schema 2，不改变账号字段和旧版密码格式。旧库在首次正常打开时创建附加表，旧版可忽略此表。

应用键只使用规范化进程文件名，不保存完整程序路径或窗口标题。应用排序不作为安全边界，也不证明 Chrome 的域名。详情仅在需要的验证通过后读取，状态离开和锁定时清空 UI 中的秘密；查看、编辑、删除与填充使用不同单次授权动作。

安装文件与用户数据分离；默认数据目录继续为 %LOCALAPPDATA%\PasswordHelper。安装和卸载不处理此目录，完整还原仍由应用中当前主密码验证及持久提交清单完成。
