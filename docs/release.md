# 首次公开发布与后续更新

主品牌为 Keyisle，中文简介名为“密屿”。源代码采用 MIT，第三方组件通知随安装包和便携包提供。

## 首次发布

1. 完成发布候选版的功能、安装、覆盖升级、卸载及数据保留验证。
2. 通过 GitHub 官方浏览器／设备授权登录，不在聊天或源码中提交密码和访问令牌。
3. 创建公开仓库，提交源码、MIT 许可证、第三方通知、说明和验证资料；排除密码库、备份、构建缓存、日志、真实凭据和签名私钥。
4. 固定发布仓库，记录安装包代码签名状态。应用内更新需完成检测、下载校验和实际升级验证后另行启用。
5. 以同一个最终构建生成 `Keyisle-1.0.0-Setup-x64.exe`、便携 ZIP 和校验清单。先准备草稿 Release，核对版本、截图与附件，再公开发布。

公开源码仓库为 [dfx1822375/Keyisle](https://github.com/dfx1822375/Keyisle)，`v1.0.0` 已发布。安装包、便携包和校验清单统一从[最新版下载页](https://github.com/dfx1822375/Keyisle/releases/latest)获取。应用内更新通道尚未启用，当前通过下载页手动升级。

## 更新约定

用户接受的流程为：定期检测并提示 → 用户确认后下载 → 核对来源及完整性／发布真实性 → 安装前处理草稿、锁库并退出 → 覆盖升级保留数据。

版本检查和下载不携带密码库、账号、搜索内容或 Windows 凭据。网络操作须在后台完成，有超时、失败反馈与取消；新版本出现时不得打断填写或验证。自动检查应可关闭，并提供手动检查入口。

可信更新需要固定发布仓库和验证规则。未来启用自动执行安装时，应验证独立签名的更新清单或受信任发布者签名；SHA-256 与下载地址来自同一个可修改页面时，不能把它们当作独立的发布者认证。下载失败、版本倒退、签名不符或文件被修改时不执行。

## 本地构建和交付

`build-windows.sh` 构建程序；`generate-icon.ps1` 生成 ICO；`generate-notices.py` 从锁定依赖及固定上游提交的许可缓存生成通知；`build-installer.py` 构建 NSIS 安装器。测试变体只改变注册表和快捷方式位置，避免写入用户真实的安装或启动登记。

`package-release.py` 只收录白名单文件，更新兼容的固定测试入口，并归档本轮诊断，仅保留最近三个发布版本。公开安装包、便携包和源码必须对应同一版本，上传前独立核对哈希、ZIP CRC 和附件内容。
