# 首次公开发布与后续更新

主品牌为 Keyisle，中文简介名为“密屿”。源代码采用 MIT，第三方组件通知随安装包和便携包提供。

## 首次发布

1. 完成发布候选版的功能、安装、覆盖升级、卸载及数据保留验证。
2. 通过 GitHub 官方浏览器／设备授权登录，不在聊天或源码中提交密码和访问令牌。
3. 创建公开仓库，提交源码、MIT 许可证、第三方通知、说明和验证资料；排除密码库、备份、构建缓存、日志、真实凭据和签名私钥。
4. 固定发布仓库，记录安装包代码签名状态。应用内更新需完成检测、下载校验和实际升级验证后另行启用。
5. 以源码标签对应的最终构建生成安装包、便携 ZIP、校验清单和签名更新清单。将附件上传至 GitHub Release 草稿，核对版本及哈希后再公开发布。

公开源码仓库为 [dfx1822375/Keyisle](https://github.com/dfx1822375/Keyisle)。安装包、便携包和校验清单可从[最新版下载页](https://github.com/dfx1822375/Keyisle/releases/latest)获取。内置更新客户端需要发布页附带签名清单 `update.json`，才能检测并安装该发布版本。

## 更新约定与发布签名

用户流程为：后台定期检测并温和提示 → 用户在“关于 Keyisle”确认下载 → 验证 ECDSA P-256 发布者签名、防降级版本比较及安装包 SHA-256 → 安装前保护未保存草稿、清空受保护剪贴板、锁库并释放单实例锁 → 覆盖升级保留全部用户数据并自动重启。

版本检查和下载使用系统原生 `WinHTTP`（禁用 Cookie 与凭据附带），绝不携带密码库、账号、搜索内容或 Windows 凭据。网络操作在后台完成，具备超时、进度显示、失败反馈与取消；新版本提示绝不打断快捷填充悬浮框或敏感项验证。自动检查可在设置中关闭，并在设置页自动更新选项旁及“关于 Keyisle”均提供“检查更新”手动检测入口。

便携版在线升级仅替换当前运行的程序文件。需要同步便携包内的说明、截图和许可证时，可下载并解压完整新版便携包。

发布签名私钥保存在仓库外的构建目录 `keys/release-signing.pem`（或通过 `KEYISLE_SIGNING_KEY` 指定），对应公钥保存在 `assets/release-public.pem` 并内置于客户端源码中。每次执行 `scripts/package-release.py` 发布新版本时，会自动对版本号、固定仓库下载地址、文件大小、安装包／便携包／主程序 SHA-256 及更新说明摘要生成 `update.json` 签名，发版时将 `Keyisle-<版本>-Setup-x64.exe`、`Keyisle-<版本>-Windows-x64-portable.zip`、`update.json` 与 `SHA256SUMS` 一并上传到对应 GitHub Release（标签 `v<版本>`）即可让旧版客户端自动识别并一键覆盖升级。

签名私钥应保存在仅发布者可访问的位置。若存放在 WSL 挂载的 Windows 盘，需核对 Windows 文件权限，避免继承对其他用户开放的目录权限。

## 本地构建和交付

`build-windows.sh` 构建程序；`generate-icon.ps1` 生成 ICO；`generate-notices.py` 从锁定依赖及固定上游提交的许可缓存生成通知；`build-installer.py` 构建 NSIS 安装器。测试变体只改变注册表和快捷方式位置，避免写入用户真实的安装或启动登记。

`package-release.py` 只收录白名单文件，更新兼容的固定测试入口，并归档本轮诊断，仅保留最近三个发布版本。公开安装包、便携包和源码必须对应同一版本，上传前独立核对哈希、ZIP CRC 和附件内容。
